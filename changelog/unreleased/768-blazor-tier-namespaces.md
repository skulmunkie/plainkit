The generated Blazor components of the component, page and shell tiers move out of `PlainKit.Blazor` into tier namespaces: `PlainKit.Blazor.Components` (`PkTabs`, `PkKanban`, `PkDetailLayout`, `PkFieldList`, `PkImageGallery` ...), `PlainKit.Blazor.Pages` (`PkWizardPage`, `PkRecordPage` ...) and `PlainKit.Blazor.Shells` (`PkAppShell`). Base elements (`PkButton`, `PkCard`, `PkInput` ...) stay in `PlainKit.Blazor`. The tier is read from the element's `meta.json`, so a component's namespace follows its element. Razor markup does not resolve a tag through a C# alias (RZ10012), so add one line per tier to `_Imports.razor`: `@using PlainKit.Blazor.Components`, `@using PlainKit.Blazor.Pages`, `@using PlainKit.Blazor.Shells`; in C# files add the matching `using` lines. The hand-written components follow their element's tier too: `PkAppBarSearch`, `PkDock`, `PkPageHeader` and `PkDataTable<TItem>` are in `PlainKit.Blazor.Components`; `PkSettingsPage`, `PkToolPage` and `PkListPage<TItem>` in `PlainKit.Blazor.Pages`; `PkTable<TItem>`, `PkSideNav`, `PkGallery`, `PkRecordForm` and the Blazor-only helpers stay in `PlainKit.Blazor`. The package now ships `buildTransitive/PlainKit.Blazor.targets` (generated from the same tier data), which adds `<Using Include="PlainKit.Blazor.Components" />`, `.Pages` and `.Shells` and, for one minor version, an alias per moved non-generic component (`<Using Include="PlainKit.Blazor.Components.PkTabs" Alias="PkTabs" />`), so a consumer's C# (`typeof`, `@ref` fields, code-behind, `OpenComponent`) compiles without edits; it is a `.targets` because the SDK already writes `buildTransitive/PlainKit.Blazor.props`. It is read by the C# SDK targets (.NET 6 SDK and later) and ignored by an older SDK and by other languages, so it is harmless there. The generic components `PkDataTable<TItem>` and `PkListPage<TItem>` cannot be aliased: they resolve through the namespace usings in C#, and every Razor tag needs the `@using` lines above. Also act on, if you have not yet: `PkDataList` is `[Obsolete]` for `PkDataTable` and `LoadAllIds` is replaced by the query (`args.ToRequest()`); `PkStat.OnClick` is an `EventCallback<PkActivateEventArgs>` and `PkStat.Tone` is nullable; `PkEmptyState.DescriptionContent` is now `ChildContent`.
