The generated Blazor components of the component, page and shell tiers move out of `PlainKit.Blazor` into tier namespaces: `PlainKit.Blazor.Components` (`PkTabs`, `PkKanban`, `PkDetailLayout`, `PkFieldList`, `PkImageGallery` ...), `PlainKit.Blazor.Pages` (`PkWizardPage`, `PkRecordPage` ...) and `PlainKit.Blazor.Shells` (`PkAppShell`). Base elements (`PkButton`, `PkCard`, `PkInput` ...) stay in `PlainKit.Blazor`. The tier is read from the element's `meta.json`, so a component's namespace follows its element. Razor markup does not resolve a tag through a C# alias (RZ10012), so add one line per tier to `_Imports.razor`: `@using PlainKit.Blazor.Components`, `@using PlainKit.Blazor.Pages`, `@using PlainKit.Blazor.Shells`; in C# files add the matching `using` lines. Generated `global using` aliases for the old names keep the package's own C# (`typeof`, `@ref` fields, `OpenComponent`, code-behind) compiling for one minor version. Also act on, if you have not yet: `PkDataList` is `[Obsolete]` for `PkDataTable` and `LoadAllIds` is replaced by the query (`args.ToRequest()`); `PkStat.OnClick` is an `EventCallback<PkActivateEventArgs>` and `PkStat.Tone` is nullable; `PkEmptyState.DescriptionContent` is now `ChildContent`.
