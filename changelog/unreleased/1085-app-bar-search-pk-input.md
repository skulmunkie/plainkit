The pk-app-bar-search field is now a `pk-input` (type search) instead of a raw `<input>`, so the last tier-tags baseline entry is paid. pk-input gains the property-only `listbox` (an element): it makes the inner input a combobox (`role="combobox"`, `aria-autocomplete="list"`, `aria-expanded` from the listbox's `hidden` state) and sets `aria-controls` and `aria-activedescendant` through `ariaControlsElements` and `ariaActivedescendantElement`, naming the option marked `aria-selected="true"`, so the listbox can live in a host's shadow tree where an ID cannot reach (call `requestUpdate()` after showing, hiding or re-marking it). Needs Chrome 135, Safari 16.4 or Firefox 136; in an older browser the two references do nothing and the role, name and expanded state still apply. Breaking for code that reached into pk-app-bar-search: its `control` part is now the pk-input host (`value`, `focus()` and the `input` event work as before, but `::part(control)` no longer styles a native input, and a native `aria-activedescendant` attribute is no longer set); the highlighted result is marked `aria-selected="true"` instead of `data-hl`; `aria-controls`/`aria-expanded` are no longer attributes on a light-tree input. The `box-icon` part is kept (exported from the pk-input's search icon). No Blazor change (the new prop is property-only).
