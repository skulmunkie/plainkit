The dev-tool modules (code explorer, console, dev tools dock, layout builder, log settings, logs, performance, quality, scorecard, theme editor) are their own unit, `dist/modules/`, with their own `manifest.json` (sizes and SRI hashes) and their own release zip `plainkit-modules-<version>.zip`; the runtime `dist/` (elements, `plainkit.css`, `js/`, icons, gallery, manifest, skills) holds no tool, and a page that only uses `pk-*` elements never fetches one. Paths move: `dist/theme-editor/theme-editor.js` becomes `dist/modules/theme-editor/theme-editor.js`, and likewise for every tool (in PlainKit.Blazor, `_content/PlainKit.Blazor/plainkit/modules/<tool>/`; the components are unchanged). A module reaches the runtime by relative paths (`../../js/`, `../../plainkit.css`); to host the modules apart from the runtime, add `<meta name="plainkit-runtime" content="...">` and an import map (`core/README.md`, "The two units"). The npm package `plainkit` carries the runtime only. The old `js/code-explorer/*.js` re-export files are no longer in `dist/js/`; import the code explorer from `dist/modules/code-explorer/`. The theme editor's Custom SDK export reads and re-hashes both units.
