The dock's header collapse-toggle and rail-button are now pk-button elements (variant plain, disclosure), keeping the parts `collapse-toggle` and `rail-button`. The hand-drawn `chevron` part is removed: the button draws its own. Migration: delete or move any host rule that targets the dock's `chevron` part (`pk-dock::part(chevron)`); the chevron is now the pk-button disclosure marker, so colour or size it through the `--pk-button-*` hooks on `collapse-toggle` or `rail-button`. The expanded state is the button's `pressed`, which its inner control reports as `aria-expanded`; `aria-haspopup` (rail) and `aria-controls` (body or flyout) are still set, through the new pk-button props below. Host CSS that styled the raw button box now styles the pk-button host through the `--pk-button-*` hooks. pk-button gains `haspopup` (reflected to the control as `aria-haspopup`) and the property-only `controls` (an element or array of elements, set as the control's `aria-controls` through `ariaControlsElements`, so it can name an element across a shadow boundary; needs Chrome 135, Safari 16.4 or Firefox 136 and does nothing in older browsers, where `aria-expanded` still announces the state). Blazor: PkButton gets `Haspopup`.
