# Elements: Form layout

> Plainkit 0.1.0-alpha.1. Generated by scripts/build-skills.mjs from core/dist/elements/api.json. Do not edit: change the source and run the generator.

Every element also takes the usual HTML global attributes (`id`, `class`, `slot`, `hidden`, `aria-*`, `data-*`). Never use a `style` attribute (the CSP blocks it): use props, parts and CSS custom properties.

## `pk-field`

**Field** (Form layout). The label, help, error, warning and counter around a form control, with the wiring between them. It hands its label and messages to the control, because ids do not cross shadow roots.

It is delegates focus to its inner control.

**Props** (set as an attribute in kebab-case, or as a property in camelCase; a boolean is present or absent)

| Attribute | Property | Type | Default | Values | Description |
|---|---|---|---|---|---|
| `label` | `label` | string | `""` |  | The label text (or use the label slot). |
| `help` | `help` | string | `""` |  | Help text under the control. |
| `error` | `error` | string | `""` |  | An error message; puts the control into the invalid state. |
| `warning` | `warning` | string | `""` |  | A warning message; puts the control into the warning state. |
| `required` | `required` | boolean | `false` |  | Marks the field required (a star, and required on the control). |
| `max` | `max` | number | `0` |  | Counter maximum: shows length / max and turns warm from 90% and red past the max; 0 hides the counter. |
| `layout` | `layout` | enum | `"stack"` | `stack` `row` `inline` | stack puts the label above the control; row puts it in a fixed column beside it (stacks on a phone); inline puts label and control on one line at their natural width. |
| `size` | `size` | enum | `"md"` | `md` `sm` | sm is the compact field of a toolbar or filter row: smaller label, tighter gap. |

**Slots** (`slot="name"` on a child)

| Slot | Description |
|---|---|
| (default) | The control: an pk-* form control or a native input, select or textarea. |
| `label` | A rich label (overrides the label prop). |
| `label-action` | A small action beside the label, such as a reset to source button (a pk-button size mini, variant ghost). Clicking it does not focus the control. |
| `help` | Rich help text (overrides the help prop). |

**CSS parts** (`::part(name)`)

| Part | Description |
|---|---|
| `field` | The grid that lays out label, control and foot. |
| `label` | The label wrapper (click focuses the control). |
| `required` | The required star. |
| `foot` | The row under the control. |
| `help` | The help text. |
| `error` | The error message (a polite live region). |
| `warning` | The warning message (a polite live region). |
| `count` | The character counter. |

**CSS custom properties** (set on the element or a parent, from a stylesheet)

| Property | Default | Description |
|---|---|---|
| `--pk-field-label` | `var(--color-text)` | Label colour. |
| `--pk-field-label-width` | `9rem` | Label column width of the row layout. |

**Accessibility.** The label click focuses the control. Ids cannot cross shadow roots, so the field sets label, description (help plus error), invalid, warning and required on an pk-* control, or aria-label and aria-description on a native one. Messages are polite live regions that are empty until used; the star is aria-hidden because required is set on the control.

Example: Help, required and counter

```html
<pk-field label="Product title" required help="Shown on the storefront and invoices." max="80"><pk-input value="Widget 1 Cover A"></pk-input></pk-field>
```

Example: Error and inline label

```html
<pk-field label="SKU" error="SKU cannot contain spaces."><pk-input value="bad sku"></pk-input></pk-field>
<pk-field label="Weight" layout="row"><pk-input value="6.4"></pk-input></pk-field>
```

Example: Action beside the label

```html
<pk-field label="Release date" help="Copied from the source record."><pk-button slot="label-action" variant="ghost" size="mini">↺ Source</pk-button><pk-input value="2026-10-14"></pk-input></pk-field>
```

## `pk-field-row`

**Field row** (Form layout). A wrapping row of fields that share the width: each field grows from a 120px minimum, a wide field takes a row of its own.

**Props** (set as an attribute in kebab-case, or as a property in camelCase; a boolean is present or absent)

| Attribute | Property | Type | Default | Values | Description |
|---|---|---|---|---|---|
| `align` | `align` | enum | `"stretch"` | `stretch` `end` `center` | Vertical alignment of the fields in the row. |

**Slots** (`slot="name"` on a child)

| Slot | Description |
|---|---|
| (default) | The fields, checkboxes or switches. |

**CSS custom properties** (set on the element or a parent, from a stylesheet)

| Property | Default | Description |
|---|---|---|
| `--pk-field-row-gap` | `var(--space-4)` | Gap between the fields. |
| `--pk-field-row-margin` | `var(--space-3)` | Space below the row. |

**Accessibility.** Plain layout with no role of its own.

Example: Two fields

```html
<pk-field-row><pk-field label="First"><input></pk-field><pk-field label="Second"><input></pk-field></pk-field-row>
```

## `pk-form`

**Form validation** (Form layout). Wraps a form and shows the browser's constraint validation well: messages in each field, a summary with links, focus on the first problem, and live re-checking.

It is delegates focus to its inner control.

**Props** (set as an attribute in kebab-case, or as a property in camelCase; a boolean is present or absent)

| Attribute | Property | Type | Default | Values | Description |
|---|---|---|---|---|---|
| `validate` | `validate` | enum | `"blur"` | `blur` `input` `submit` | When to check: blur (after leaving a field, and on submit), input (while typing) or submit (only on submit). A field already showing an error re-checks as you type. |
| `show-valid` | `showValid` | boolean | `false` |  | Also shows the valid state on fields that hold a value. |
| `summary` | `summary` | boolean | `false` |  | Shows a summary of the problems with links to the fields. |

**Slots** (`slot="name"` on a child)

| Slot | Description |
|---|---|
| (default) | A form element. |
| `summary-title` | The summary heading. |

**Events** (`addEventListener`; `pk-*` events are CustomEvents whose `detail` is shown)

| Event | Detail | Description |
|---|---|---|
| `pk-invalid` | `{ count: number, controls: Element[], messages: string[] }` | A submit was stopped because these controls are invalid. |
| `pk-valid` | `null` | A submit passed validation. |

**Methods**

| Method | Description |
|---|---|
| `validateAll()` | Checks every control now; returns true when all are valid. |

**CSS parts** (`::part(name)`)

| Part | Description |
|---|---|
| `summary` | The problem summary box. |
| `summary-title` | The summary heading. |
| `summary-list` | The list of problems. |

**CSS custom properties** (set on the element or a parent, from a stylesheet)

| Property | Default | Description |
|---|---|---|
| `--pk-form-summary-bg` | `var(--color-surface-alt)` | Summary background. |

**Accessibility.** Turns the native bubble off and puts each message in the field as a polite live region with aria-invalid on the control; the first invalid control takes focus on submit; the summary is role=alert and its links move focus. Custom text per constraint: data-msg-required, data-msg-type, data-msg-pattern, data-msg-min, data-msg-max on the control.

Example: Validated form with summary

```html
<pk-form summary>
  <form>
    <pk-field label="Name" required><pk-input name="name" required data-msg-required="Enter a name."></pk-input></pk-field>
    <pk-field label="Email" required><pk-input name="email" type="email" required data-msg-type="Use the form name@example.com."></pk-input></pk-field>
    <pk-button type="submit">Save</pk-button>
  </form>
</pk-form>
```

## `pk-form-actions`

**Form actions** (Form layout). The bar of buttons under a form, aligned start, end or between, and sticky to the bottom of a long form.

**Props** (set as an attribute in kebab-case, or as a property in camelCase; a boolean is present or absent)

| Attribute | Property | Type | Default | Values | Description |
|---|---|---|---|---|---|
| `sticky` | `sticky` | boolean | `false` |  | Sticks to the bottom of the scrolling area with a top edge, clearing the phone home indicator. |
| `align` | `align` | enum | `"start"` | `start` `end` `between` | Where the buttons sit. |

**Slots** (`slot="name"` on a child)

| Slot | Description |
|---|---|
| (default) | The buttons. |
| `status` | A status message such as "Unsaved changes". |

**CSS parts** (`::part(name)`)

| Part | Description |
|---|---|
| `bar` | The bar. |
| `status` | The status text. |

**CSS custom properties** (set on the element or a parent, from a stylesheet)

| Property | Default | Description |
|---|---|---|
| `--pk-form-actions-bg` | `var(--color-panel)` | Background of a sticky bar. |

**Accessibility.** Plain layout; the status text is not a live region (use a Notice for announcements). On a phone the buttons of a sticky bar share the width.

Example: End-aligned

```html
<pk-form-actions align="end"><pk-button variant="ghost">Cancel</pk-button><pk-button>Save</pk-button></pk-form-actions>
```

## `pk-form-section`

**Form section** (Form layout). A titled section of a form: heading and description beside a responsive grid of fields (stacked below 1024px).

**Props** (set as an attribute in kebab-case, or as a property in camelCase; a boolean is present or absent)

| Attribute | Property | Type | Default | Values | Description |
|---|---|---|---|---|---|
| `heading` | `heading` | string | `""` |  | The section heading (or use the heading slot). |
| `description` | `description` | string | `""` |  | A sentence under the heading. |

**Slots** (`slot="name"` on a child)

| Slot | Description |
|---|---|
| (default) | The fields. Give a child class form-span to make it span the full width. |
| `heading` | A rich heading. |
| `description` | A rich description. |

**CSS parts** (`::part(name)`)

| Part | Description |
|---|---|
| `section` | The two-column grid. |
| `head` | The heading block. |
| `title` | The heading (h2). |
| `description` | The description. |
| `body` | The grid of fields. |

**CSS custom properties** (set on the element or a parent, from a stylesheet)

| Property | Default | Description |
|---|---|---|
| `--pk-form-section-column` | `14rem` | Minimum column width of the field grid. |

**Accessibility.** The heading is a real h2 so the section is navigable by heading; the fields keep their own labels.

Example: Two sections

```html
<pk-form-section heading="Profile" description="Shown on invoices."><pk-field label="Business name"><pk-input></pk-input></pk-field><pk-field label="Website"><pk-input type="url"></pk-input></pk-field></pk-form-section>
```
