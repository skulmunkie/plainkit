# Changelog

All notable changes to Plainkit (the `plainkit` npm package and the `PlainKit.Blazor` NuGet package, versioned together).
The format follows [Keep a Changelog](https://keepachangelog.com/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

- Alpha status of PlainKit.Blazor: Blazor Server is verified in a live host; Blazor WebAssembly is not verified. Not yet available as components: `PkCard`, `PkEmptyState`, `PkFieldList`, `PkStat`, `PkTable` (data grid). Not generated: 17 wrapper-only parameters (`PkAlert` `Boxed`, `Compact`, `Inline`; `PkAppShell` `ErrorOverlayMessage`, `ShowErrorOverlay`; `PkDialog` `CloseButtonLabel`, `FooterAlignEnd`, `OverFlyout`, `ShowCloseButton`; `PkDrawer` `Backdrop`, `IsLoading`, `PhoneCards`; `PkTooltip` `DocLink`, `ExternalLink`, `LoadAsync`, `OnClick`, `Title`) plus `PkDialog.MaxWidthPx` (a CSS custom property), and 4 parameters whose app-era type is not defined (issue #9): `PkChart.Data`, `PkImageGallery.Images`, `PkDialog.Theme`, `PkTooltip.Kind`. See the "Alpha status" section of the package README.
- Fixed: the NuGet package no longer contains `Generated/generated.manifest.json` (it was packed as `content/` and `contentFiles/` and copied into consumers' projects); `scripts/tests/blazor-package.test.mjs` guards it.
- Fixed: every public enum and member in PlainKit.Blazor (`PkTheme`, `PkWidth`, `PkChrome`, `PkGalleryKind`, `PkLogLevel`) has an XML doc comment, so the build has no CS1591 warnings.
- Changed: the gallery's Guides page says "Coming soon" (a `pk-badge` above the empty state); the docs engine is undecided (issue #6).
### Breaking

- Changed (breaking): the code explorer element is now `<pk-code-explorer>` (was `<code-explorer>`), its events `pk-code-explorer-open` and `pk-code-explorer-error` (were `code-explorer-open` and `code-explorer-error`) and its height hook `--pk-code-explorer-height` (was `--code-explorer-height`), following the `pk-` naming rule (issue #12). There is no alias for the old tag. `mountCodeExplorer`, the module name and the JS exports are unchanged; `PkCodeExplorer` in Blazor is unaffected.

- Fixed: PlainKit.Blazor no longer throws out of the request pipeline when `IPkLog` (or a component) touches JavaScript while a page is prerendered; `PkRuntime.DisposeAsync` now ignores the "JavaScript interop calls cannot be issued at this time" error of a prerender scope. Found by driving the Playground in a real browser.
- Added: the `/_plainkit` dev tools page in PlainKit.Blazor has a Logs tab (`PkLogs` and `PkLogSettings`), as the logging documentation said it did; the Playground has a `/generated` page that exercises the generated components (binds, dialog, events, an enum, `IPkLog`) with the `ILogger` forwarder on.

- Changed: `pk-dialog`, `pk-drawer` and `pk-popover` install the declarative openers (`data-open`, `data-toggle`, `data-close`, `js/invokers.js`) the first time one connects, so a page that only uses the elements gets them without `initPlainkit()`, and a page with no overlay does not load the listener's work; `initPlainkit()` still installs them (idempotent per root). The overlays-and-navigation sample no longer wires them itself. Element sources changed, so the browser attestation must be re-run (issue #20).
- Added: PlainKit.Blazor logging bridge (issue #19). `PkOptions.Logging` (`PkLoggingOptions`) sets the SDK level, per-scope levels and routes at startup and can forward SDK entries to `ILogger` (category `PlainKit.<scope>`, debug/info/warn/error mapped to Debug/Information/Warning/Error, minimum level and scope filters, off by default); the new `IPkLog` service writes entries into the SDK log from Blazor code and changes its settings. Entries written from .NET are not echoed back, and the JS sink and `DotNetObjectReference` are disposed with `PkRuntime`. Bridge functions: `configureLogging`, `writeLog`, `startLogForwarding`, `stopLogForwarding`.
- Added: the gallery inspector shows element details (issue #24). On an element page the docked "Details" drawer lists the tag, summary, properties (type, default), slots, events with their detail, CSS parts and custom properties, methods and plus the live markup of the playground with a copy button, updated as the playground changes; on any other page it is a `pk-empty-state` saying what it shows. The drawer, resize handle and persisted width are unchanged, and on a phone it stays a drawer opened by "Details". The inspector is reusable: `createElementInspector(container)` in `js/element-inspector.js` (`show({ meta, element, extraSections })`, `refresh()`, `destroy()`), with pure logic in `js/element-inspector-logic.js` (`describeElement`, `cleanMarkup`), for the layout builder (issue #30) to use for the selected element. A host adds its own sections with `extraSections` (`{ title, render(container, { meta, element }) }`); the core inspector knows nothing about Blazor.
- Fixed: `pk-tree` no longer throws `aria is not a function` when it connects with items that are already in the page but not upgraded yet; it waits for `pk-tree-item` to be defined and updates again (issue #21).
- Fixed: the close button of a closable `pk-tab` is reachable by keyboard: it is a tab stop on the selected tab (the other tabs' buttons stay out, like the tabs themselves), and Enter or Space closes (issue #21).
- Fixed: a `flush` `pk-card` with a `heading` keeps the padding of its heading row and drops only the body padding (issue #21).
- Fixed: `pk-otp-input` no longer overflows a 320px window: the host and group are capped at 100% and the cells shrink below 2.75rem when the container is narrower (issue #21).
- Added: `pk-nav-item` `group` (a group title in `pk-side-nav`: static, muted text, not focusable, skipped by the arrow keys, hidden while filtering, a divider in the icon rail); `pk-progress` `inline` (label, bar and value on one line); `pk-app-shell` `flush` (no body padding, so a workspace sits edge to edge; the safe-area insets stay); `pk-workspace` `--pk-workspace-nav-pad`, `--pk-workspace-main-pad` and `--pk-workspace-aside-pad` (per-pane padding, each falling back to `--pk-workspace-pad`); `pk-grid` `ratio` (unequal columns such as `2:1`, back to auto columns at 640px and below; new `--pk-grid-ratio`); `pk-input` `showLabel` (a visible label linked to the control, new `label` part). Each new prop has its `blazor/mappings` parameter (`Group`, `Inline`, `Flush`, `Ratio`, `ShowLabel`) (issue #21).
- Changed: `pk-input` was at its 4 KB gzip element budget, so its source was tightened to fit the new label (one shared number reader for min, max and step, one event helper, one phone media query, the unused textarea and select selectors and the outer spin-button selector dropped); no budget was raised.
- Added: the Blazor element wrappers are generated (issue #2). `node scripts/generate-blazor.mjs` reads `core/dist/elements/api.json` and `blazor/mappings/<name>.json` and writes one Razor component per element into `blazor/src/PlainKit.Blazor/Generated/` (80 components, the enums they use, one event-args class per `pk-*` event, and `generated.manifest.json` listing what was skipped or still needs a type). Props become parameters, slots `RenderFragment`s, events `EventCallback`s with typed details, and a value driven by a change event is two-way (`@bind-Value`). `PkElementBase` loads the toolkit through `PkRuntime`; `wwwroot/PlainKit.Blazor.lib.module.js` (a Blazor JavaScript initializer, also generated) registers the `pk-*` events with Blazor. `--check` fails when the output is stale; CI runs it and the definition of done lists it. `PkCard`, `PkEmptyState`, `PkFieldList`, `PkStat` and `PkTable` (mapping `existing: true`) and `PkGallery` (hand-written) are skipped; `blazor/mappings/gallery.json` is now marked `existing`.
- Added: the SDK logs what it used to swallow (issue #16). Empty catch blocks and `.catch(() => {})` handlers in the runtime now log (warn, or debug for an expected fallback) or say why they are silent, and `tests/no-silent-catch.test.mjs` keeps it so; elements warn once per instance and prop when an enum value, a number or json cannot be used (`coerce` takes an optional report callback), and `pk-tabs` (value with no tab), `pk-icon` (name not in the sprite), `pk-image-gallery` (refused source), `pk-dialog` and `pk-drawer` (opened with no content), `pk-table` (columns or rows not an array) and `pk-input` (bad currency) say what went wrong; debug lines cover element defined, connected and prop changes, module load times and each tool's mount. New exports: `isLogEnabled(level, scope)` in `js/log.js`; `PkElement` gains `log`, `warnOnce` and `coerceProp`. `loadElements` no longer rejects (it logs a failed registry or module load).
- Changed: the Blazor mapping moved out of the SDK element metadata into `blazor/mappings/<element>.json` (issue #26). The `blazor` block is gone from every `core/elements/*/*.meta.json` and from `dist/elements/api.json`; `validateApi` no longer requires it; the SDK gallery no longer shows the "Blazor equivalent" snippet and the "Blazor mapping" table (`blazorSnippet` is removed). The mapping checks now live in `scripts/tests/blazor-mappings.test.mjs` (run by CI and the release workflow). Parameters whose type is not defined in this repository yet are marked `todo` (issue #9).
- Added: logs viewer (`mountLogs`, issue #17) and logging settings (`mountLogSettings`, issue #18), built from SDK components: filter the SDK logger's entries by level, scope and text, see a row's detail, copy/export/import JSON, pause; set the global level, a level per scope and where each level is sent, send a test, save and reset. They are `dist/logs/` and `dist/log-settings/`, the dev tools' Logs and Logging tabs, a Logging section on the Settings page, and the `PkLogs` and `PkLogSettings` Blazor components.
- Added: versioning (issue #23): one version for the SDK and PlainKit.Blazor in `core/VERSION`, stamped into `dist/manifest.json`, `js/version.js` (`PK_VERSION`) and the NuGet package (`PkAssets.Version`, `PkRuntime.GetSdkVersionAsync`); `tools/versioning.mjs` (check, set, bump); the API baseline now covers each element's tag, props, events, slots, parts, CSS properties and methods; CI checks a release pull request; the release workflow checks the tag and marks pre-releases.
- Removed (breaking): the class-based components. `core/components/` (35 folders) and its cascade file `order.json` are deleted, and so are `dist/plainkit-compat.css`, `dist/plainkit-compat.min.css` and `dist/components/`. Every component is a `pk-*` element; `dist/plainkit.css` (tokens and the page layer) is the only stylesheet, and the tool modules and gallery frames load it alone. `PkAssets.CompatCss` and the compat link in `PkStyles` are gone.
