# Changelog

All notable changes to Plainkit (the `plainkit` npm package and the `PlainKit.Blazor` NuGet package, versioned together).
The format follows [Keep a Changelog](https://keepachangelog.com/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.2.0-alpha.1] - 2026-09-21

### Breaking

- Changed (breaking): `pk-tooltip` no longer adds a hidden `<span>` to its own light DOM or sets `aria-describedby` on the slotted target. The target now carries `aria-description` with the tooltip text (an attribute the tooltip sets and removes again; a target that already has its own `aria-description` keeps it), and the tip stays a `role="tooltip"` node in the shadow tree. A host that read `aria-describedby` or looked for the extra child must use `aria-description` and the element's own `text`.
- Changed (breaking): `pk-tabs`, `pk-side-nav` (with `persist`) and `pk-command-palette` now raise events for changes they made themselves: `pk-tab-change` (not cancelable) when the value falls back to the first enabled tab, `pk-nav-toggle` when the collapsed state is restored from storage, and `pk-close` when the palette is closed by its shortcut (`reason: "shortcut"`, cancelable) or by choosing a command (`reason: "select"`, after the fact). A host listener that acted on every `pk-tab-change` now also hears the first-tab fallback on load.
- `PkChart.Data` is a `PkChartData?` and `PkImageGallery.Images` an `IReadOnlyList<PkGalleryImage>?` instead of `object?`, so the compiler checks what you pass; a caller that passed an anonymous object or another shape must now build the record (a `List<PkGalleryImage>` or a `PkChartData` still compiles). The attribute sent to the element is unchanged, byte for byte. The generator uses the type a mapping names for a JSON prop when the package declares it, and lists a JSON prop without a type under `typesToDefine` in the manifest (none is left). (#77)

### Added

- Added: `PkAssets.CssMin`, `PkAssets.CssVersioned`, `PkAssets.CssMinVersioned`, `PkAssets.Versioned(path)` (the file's URL with `?v=` and the first 12 characters of its SHA-384, base64url) and `PkAssets.Integrity(path)` (the `sha384-` value for an `integrity` attribute). The hashes come from the package manifest, which is embedded in the assembly and read once, so a call does no file access (#53). `PkStyles` gains `Minified`, `Versioned` and `InHead`.
- Added: `PkDialog.Size` (`PkDialogSize`: `Sm`, `Md`, `Lg`, `Xl`, `Fullscreen`; null leaves the element's own default), generated from the element's `size` (#55). `PkDialog.MaxWidthPx` (the element's `maxWidth`) is verified to work and the README no longer lists it as unsupported.
- Added: `PkPageHeader` with `Crumbs` (`IReadOnlyList<PkCrumb>`, `PkCrumb(Label, Href)`), an optional `Title` (default: the last crumb's label), `SuffixContent`, and `ShellSection` (the name of a `SectionOutlet` in the layout's shell title slot: the title is written there and not drawn twice). It renders a `pk-breadcrumb` with `aria-current="page"` on the last crumb; the route-to-crumbs lookup stays in the app. The shell's `title` slot and back link belong to the SDK's `pk-app-shell` (#54).
- Added: package README (#44): the namespaces to import, where `<PkStyles />` goes and the cascade order, the direct-link option and cache busting, the render mode, the router snippet as a fragment, a page header section, a note that `/_plainkit` renders inside the app's layout and is Development-only, which SDK warning to trigger to see the `ILogger` forwarder, and absolute GitHub links in place of repository-relative ones; the maintainer-only sections are gone.
- Added: sample patterns can ship a script (`core/samples/patterns/<id>/<id>.js`, `export default function mount(root)` returning `{ destroy() }`). The build carries it into the gallery data (`script`) and `dist/gallery/patterns/`, `preview.js` loads it after the markup, and the skills' pattern reference shows it. The notifications (a toast on demand, a bell count), unsaved-settings (a save bar that appears on change, Save and Discard), search-results (live filtering with marks, counts, an empty state and Ctrl+K), onboarding (Start advances the stepper, progress and checklist), master-detail (selecting an item fills the detail) and filter-table (toolbar search and status filter the table, applied filters as removable tags) patterns now behave like the real thing, and the `layouts/record` History tab holds a timeline instead of placeholder text. `core/tests/pattern-scripts.test.mjs` checks every script.
- Added: every two-way prop now names its commit event in the element meta (`"commit": "pk-tab-change"`, or a list such as `["pk-open", "pk-close"]`), and `core/tests/ownership.test.mjs` fails when a new `value`, `open`, `checked`, `selected`, `current`, `expanded`, `page`, `collapsed`, `index`, `pressed` or `wrap` prop names none (a prop the user never changes is listed there with the reason). The element validator checks that a named event is declared.
- Added: `pk-combo-toggle` on `pk-combobox` (`{ open }`, raised when the list opens or closes by itself, not for a host change), `pk-wrap-change` on `pk-code-block` (`{ wrap }`), `pk-reset` on `pk-form` (raised after a form reset, once the controls have their initial values again, and not when the reset was cancelled), and `pk-open` / `pk-close` declared in the meta of `pk-command-palette`, `pk-context-menu`, `pk-select-menu` and `pk-lightbox` (they were raised already). Blazor: `PkCombobox.OnToggle`, `PkCodeBlock.OnWrapChange`, `PkForm.OnReset`, `PkCommandPalette.OnOpen` and `OnClose`.
- Added: `controlled` on `pk-tag`: the tag raises `pk-remove` and never removes itself, so the host removes it from its own state. Without it nothing changes: the tag still removes itself after `pk-remove` unless a listener called `preventDefault()`. `PkTag` sets `controlled` by default (`Controlled="true"`), so a Blazor-rendered list removes a tag through its own `OnRemove` handler and never disagrees with the DOM.
- Added: the ownership and reactivity contract (`core/STANDARDS.md`, "Ownership and reactivity", and the matching "How binding works" section of the PlainKit.Blazor README): the host owns attributes and light-DOM children, the element owns its shadow tree, two-way values follow a commit event, subscriptions outside an element's subtree are added in `connected()` and removed in `disconnected()`, and the reactive core stays "attributes and properties in, one microtask-batched render, events out". Enforced by `core/tests/ownership.test.mjs` (a source guard for document, window, matchMedia, interval and observer subscriptions, plus a fake-DOM reconnect check) and `core/tests/element-surface.test.mjs` (the `PkElement` surface, its lifecycle hooks and the `{{ }}` / `data-if` syntax are frozen).
- Added: `pk-table` expandable rows (#39). `expandable` gives every row that has a `detail-<rowId>` slot a toggle button (`aria-expanded`, `aria-controls`, Enter or Space, focus kept after it toggles) that shows or hides that slot under the row; the host keeps the detail content, the table only renders its slot. `expanded` holds the open row ids and `pk-row-expand` (`{ id, index, expanded }`) reports each change. The expansion code loads on demand (`js/table-expand.js`, only when `expandable` is set) and the table's sort and filter logic moved to `js/table-data.js` (`sortKey`, `sortRows` and `filterRows` are still exported from the table module), which keeps the `pk-table` module inside its 4 KB gzip budget (3.85 KB) without raising it.
- Added: `pk-table` `emptyText` (attribute `empty-text`, default "No rows"; the `empty` slot still replaces it) and a "Loading" status for the `loading` placeholder row. The Blazor mapping gains `EmptyText`, `Expandable`, `ExpandedKeys`, `DetailTemplate` and `OnRowExpand` (`PkTable` itself is still hand-kept, not generated).
- Added: the element meta may mark a slot `dynamic` when its name is a pattern the element builds (`cell-<rowId>-<key>`, `detail-<rowId>`); `pk-table` lists both under `slots`. The agent skills now include the "Empty and loading" and "Expandable rows" examples, and the `pk-table` note in the known gaps is gone.
- Added: `PkCard`, `PkEmptyState`, `PkFieldList` and `PkStat`, hand-written over their elements (`Components/`, following `blazor/mappings`), each with the rest of the components' behaviour (unmatched attributes, `class`). `StatCardVariant` is the tone of `PkStat`; its `OnClick` is the element's `pk-activate`, registered for Blazor like the generated events. Only `PkTable` is still not available (issue #2).
- Added: `PkAlert.Boxed` (false is the plain form), `PkAlert.Inline`, `PkAlert.Compact`, `PkDialog.ShowCloseButton` (false hides the header close button) and `PkTooltip.Title` (the heading), plus `PkTooltip.LinksContent` (the `links` slot). They are plain attributes of the element; the mapping's new `invert` flag sends a negated bool (`Boxed` is `!plain`). 12 wrapper-only parameters stay unavailable, each with its reason in `generated.manifest.json` and the skills' `known-gaps.md`; `PkDialog.MaxWidthPx` is supported since the mapping sends the element's `maxWidth` (see below).
- Added: PlainKit.Blazor types for structured parameters (issue #9): `PkChartData` / `PkChartSeries` (`PkChart.Data`), `PkGalleryImage` (`PkImageGallery.Images`) and `PkTableColumn` with `PkTableColumnType` / `PkTableColumnAlign` (the table's `columns`), each sent as a camelCase JSON attribute; bUnit tests in `TypedParameterTests`. The generator emits these parameters as `object?` (it types a JSON parameter only for simple values), so the mappings carry a note naming the type instead of a `todo`; no mapping has a `todo` marker left.

### Changed

- Changed (breaking, PlainKit.Blazor): `PkStyles` renders a plain `<link>` in place instead of going through `HeadContent`. In the standard `App.razor` the head outlet comes after the app's own stylesheets, so the toolkit's base layer used to land last and override app rules (#53). Put `<PkStyles />` first in the `<head>` of `App.razor`; `InHead="true"` keeps the old behaviour. The link now carries a content-hash `?v=` (`Versioned="false"` turns it off).
- Changed (breaking, PlainKit.Blazor): `PkPageHeader` is hand-written and takes a list of crumbs (#54). `Heading` is now `Title`, `Level` starts at 1, and the default slot (beside the title) is `SuffixContent` instead of `ChildContent`; `BreadcrumbContent`, `ActionsContent`, `MetaContent` and `Variant` are unchanged.
- Changed: every Blazor component takes the attributes it has no parameter for (`id`, `data-*`, `aria-*`, `class`, ...) and puts them on its element, so `<PkButton id="x" data-test="y" aria-label="z">` works instead of throwing; a `class` is merged with the component's own (`ExtraClass` on the components that list it). `AdditionalAttributes` now lives once in `PkElementBase` (issue #44).
- Changed: the generated components build their `pk-*` event-handler dictionary once (`AddEventHandlers`, called by `PkElementBase`) instead of on every parameter change; a parameter change allocates only when the caller passed extra attributes.
- Changed: Blazor mappings use the element's real props instead of app-era types: `PkAlert.Kind` is `PkAlertKind`, `PkTooltip.Placement` is `PkTooltipPlacement`, `PkDialog` gets `Tint` (`PkDialogTint`, the element's `tint`) and `MaxWidthPx` (the element's `maxWidth`), `PkTooltip` gets `Help` and `Enrich` (booleans) and `Title` (`heading`), and the unbuilt `PkStat` and `PkTable` mappings name `Tone` (`PkStatTone`) and `Cards` (bool). Breaking for code using the earlier alpha's `NoticeKind` or `InfoTipPlacement` enums.
- Changed: the dock's Theme tab keeps room under its last row so the dev tools launcher does not cover a control (checked at 375px, dark and light).
- Changed: on a phone (640px and narrower) secondary text (`--text-meta`: chips, tags, captions, mini buttons, table headers) is 13px instead of 12px; desktop is unchanged. The page-level stylesheet stays inside its budget (9.91 of 10 KB gzip). Refs #7.
- The theme editor edits lengths (spacing, radius and other size tokens with a plain px, rem, em or % value) with a number and a unit field (`pk-unit-input`) instead of a text field; a unit pick applies at once, and other kinds of token keep their fields. The exported CSS is unchanged for unchanged values. (#13)
- Repository process: each pull request adds one changelog fragment under `changelog/unreleased/` (`node scripts/changelog.mjs new`), the release pull request compiles them into `CHANGELOG.md`, and CI checks both (label `no-changelog` for docs-only or tooling changes). Generated paths are marked `linguist-generated`, `AGENTS.md` describes the trunk-based flow for agents, and packages are published only from a version tag.
- Generated files are no longer in the repository: `core/dist`, the element modules, the Blazor wrappers, the agent skills and the package copy of `dist` are produced by `node scripts/bootstrap.mjs` (Node only, about 4 seconds) on a fresh clone, in CI and in every workflow, so pull requests carry no generated diffs and cannot conflict on them. `dotnet build` stops with a one-line instruction when they are missing, and `node core/tools/serve.mjs` generates them itself. A git tag no longer carries `core/dist`, so the jsDelivr-by-tag link is no longer advertised: pinned versions are the GitHub release zip and the NuGet package, and the Pages site is the latest `main`.
- Continuous integration runs as small parallel jobs with path filters, caching and a per-job time budget; `node scripts/verify.mjs` runs the same checks locally and every failure prints a `FIX:` line, and a failed pull request gets one sticky comment listing them.
- The changelog check (`scripts/changelog.mjs check-pr`) treats the browser attestation report (`core/tests/browser/report.json`) like docs: a pull request that only refreshes it needs no fragment.
- `PkTable` is no longer in the "do not exist yet" list; it and `PkDataList` are documented in the package README and the skills.
- The `pk-workspace` `active-pane` docs say that a tab tap raises a cancelable `pk-pane-change` first, and that a host that owns the pane from a route calls `preventDefault()` and changes the route instead. (#51)
- A third activation of the same `pk-table` header clears the sort, so a list can return to its natural order: `pk-sort` then carries a null `key` and `direction` (a `manual` table reports it too), `sort` becomes empty and `sortBy(null)` does the same. The cycle was ascending and descending only. (#63)

### Fixed

- Fixed: `pk-tooltip` and `pk-tag` no longer write into nodes a host such as Blazor renders (ownership audit, rule 3): the tooltip adds no light-DOM node, and a `controlled` tag leaves its removal to the host.
- Fixed: `pk-combobox`, `pk-command-palette` and `pk-code-block` opened, closed or toggled a two-way prop without raising an event (see Added). `pk-combobox` also drops a stale search text after choosing an option.
- Fixed: the theme editor's Import reported "Imported" and cleared every override for text that was neither JSON nor CSS (or held no usable token); it now shows an error in its alert, logs a warning through the SDK logger and leaves the overrides untouched. An explicit `{"shared":{},"dark":{},"light":{}}` still clears.
- Fixed: `pk-select`, `pk-radio-group` and `pk-combobox` wired their inner listeners again every time they were moved in the DOM, so a change event fired twice after a reconnect; they now wire once.
- Fixed: `pk-breadcrumb`, `pk-side-nav` and `pk-workspace` never removed their `matchMedia` listener, which kept a removed element alive; it is now removed in `disconnected()`. `pk-toc` removes its scroll listener from the element it was added to (also when `scroller` changes) and cancels its pending frame.
- Fixed: `pk-split-button`, `pk-nav-item` and `pk-context-menu` lost their outside-click dismissal when re-attached while open; `pk-local-time` no longer starts its refresh timer on a detached element; the code explorer no longer keeps a change-feed subscription that resolves after it was disconnected.
- Fixed: `PkElement.watchSlot` adds one `slotchange` listener per slot however often `connected()` runs (tabs, cards, avatar groups and others stacked one per move).
- Fixed: PlainKit.Blazor's mount components (`PkLogs`, `PkScorecard`, `PkConsole`, `PkPerformance`, `PkCodeExplorer`, `PkLogSettings`) leaked a running tool when they were disposed while its module was still loading; the bridge now drops a mount that is no longer current.
- Fixed: the Gallery workspace of `/_plainkit/{workspace}` framed a 404: `<pk-gallery>` resolves its `src` against the page's URL, so the relative address missed under a routed path. The page now passes an absolute address.
