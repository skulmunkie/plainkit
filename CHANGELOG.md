# Changelog

All notable changes to Plainkit (the `plainkit` npm package and the `PlainKit.Blazor` NuGet package, versioned together).
The format follows [Keep a Changelog](https://keepachangelog.com/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Added: the ownership and reactivity contract (`core/STANDARDS.md`, "Ownership and reactivity", and the matching "How binding works" section of the PlainKit.Blazor README): the host owns attributes and light-DOM children, the element owns its shadow tree, two-way values follow a commit event, subscriptions outside an element's subtree are added in `connected()` and removed in `disconnected()`, and the reactive core stays "attributes and properties in, one microtask-batched render, events out". Enforced by `core/tests/ownership.test.mjs` (a source guard for document, window, matchMedia, interval and observer subscriptions, plus a fake-DOM reconnect check) and `core/tests/element-surface.test.mjs` (the `PkElement` surface, its lifecycle hooks and the `{{ }}` / `data-if` syntax are frozen).
- Added: `pk-table` expandable rows (#39). `expandable` gives every row that has a `detail-<rowId>` slot a toggle button (`aria-expanded`, `aria-controls`, Enter or Space, focus kept after it toggles) that shows or hides that slot under the row; the host keeps the detail content, the table only renders its slot. `expanded` holds the open row ids and `pk-row-expand` (`{ id, index, expanded }`) reports each change. The expansion code loads on demand (`js/table-expand.js`, only when `expandable` is set) and the table's sort and filter logic moved to `js/table-data.js` (`sortKey`, `sortRows` and `filterRows` are still exported from the table module), which keeps the `pk-table` module inside its 4 KB gzip budget (3.85 KB) without raising it.
- Added: `pk-table` `emptyText` (attribute `empty-text`, default "No rows"; the `empty` slot still replaces it) and a "Loading" status for the `loading` placeholder row. The Blazor mapping gains `EmptyText`, `Expandable`, `ExpandedKeys`, `DetailTemplate` and `OnRowExpand` (`PkTable` itself is still hand-kept, not generated).
- Added: the element meta may mark a slot `dynamic` when its name is a pattern the element builds (`cell-<rowId>-<key>`, `detail-<rowId>`); `pk-table` lists both under `slots`. The agent skills now include the "Empty and loading" and "Expandable rows" examples, and the `pk-table` note in the known gaps is gone.

### Fixed

- Fixed: `pk-select`, `pk-radio-group` and `pk-combobox` wired their inner listeners again every time they were moved in the DOM, so a change event fired twice after a reconnect; they now wire once.
- Fixed: `pk-breadcrumb`, `pk-side-nav` and `pk-workspace` never removed their `matchMedia` listener, which kept a removed element alive; it is now removed in `disconnected()`. `pk-toc` removes its scroll listener from the element it was added to (also when `scroller` changes) and cancels its pending frame.
- Fixed: `pk-split-button`, `pk-nav-item` and `pk-context-menu` lost their outside-click dismissal when re-attached while open; `pk-local-time` no longer starts its refresh timer on a detached element; the code explorer no longer keeps a change-feed subscription that resolves after it was disconnected.
- Fixed: `PkElement.watchSlot` adds one `slotchange` listener per slot however often `connected()` runs (tabs, cards, avatar groups and others stacked one per move).
- Fixed: PlainKit.Blazor's mount components (`PkLogs`, `PkScorecard`, `PkConsole`, `PkPerformance`, `PkCodeExplorer`, `PkLogSettings`) leaked a running tool when they were disposed while its module was still loading; the bridge now drops a mount that is no longer current.

## [0.1.0-alpha.1] - 2026-09-21

First pre-release. The API may change at any minor version while the major is 0; breaking changes are listed here.

### Added

- Added: agent skills for developer agents building on Plainkit (issue #35), one bundle at one version (`core/VERSION`): `plainkit-sdk` and `plainkit-blazor`, generated by `node scripts/build-skills.mjs` into `core/dist/skills/<skill>/` (a short `SKILL.md` with workflows plus format-neutral `references/*.md`: every element by group, page templates, patterns and layouts, the tool modules, logging, theming, loading, the Blazor components, parameters, enums, events, options and known gaps). They are generated from `dist/elements/api.json`, `blazor/mappings`, the generator manifest, the C# sources, the sample folders and the module headers, and `scripts/tests/skills.test.mjs` verifies every code sample (real `pk-*` tags, props and slots; real `Pk*` components and parameters; real exports and options). `--check` runs in CI; `dist/skills` is in the SRI manifest (`node core/tools/build.mjs` keeps the skills it does not produce listed, and `build-skills.mjs` refreshes the manifest after writing), is copied into the Blazor package as static web assets (not content), and the release attaches `plainkit-skills-<version>.zip`. Other agent formats (`AGENTS.md`, `llms.txt`) are tracked in issue #36.
- Added: the `/_plainkit` dev tools page in PlainKit.Blazor has a Logs tab (`PkLogs` and `PkLogSettings`), as the logging documentation said it did; the Playground has a `/generated` page that exercises the generated components (binds, dialog, events, an enum, `IPkLog`) with the `ILogger` forwarder on.
- Added: PlainKit.Blazor logging bridge (issue #19). `PkOptions.Logging` (`PkLoggingOptions`) sets the SDK level, per-scope levels and routes at startup and can forward SDK entries to `ILogger` (category `PlainKit.<scope>`, debug/info/warn/error mapped to Debug/Information/Warning/Error, minimum level and scope filters, off by default); the new `IPkLog` service writes entries into the SDK log from Blazor code and changes its settings. Entries written from .NET are not echoed back, and the JS sink and `DotNetObjectReference` are disposed with `PkRuntime`. Bridge functions: `configureLogging`, `writeLog`, `startLogForwarding`, `stopLogForwarding`.
- Added: the gallery inspector shows element details (issue #24). On an element page the docked "Details" drawer lists the tag, summary, properties (type, default), slots, events with their detail, CSS parts and custom properties, methods and plus the live markup of the playground with a copy button, updated as the playground changes; on any other page it is a `pk-empty-state` saying what it shows. The drawer, resize handle and persisted width are unchanged, and on a phone it stays a drawer opened by "Details". The inspector is reusable: `createElementInspector(container)` in `js/element-inspector.js` (`show({ meta, element, extraSections })`, `refresh()`, `destroy()`), with pure logic in `js/element-inspector-logic.js` (`describeElement`, `cleanMarkup`), for the layout builder (issue #30) to use for the selected element. A host adds its own sections with `extraSections` (`{ title, render(container, { meta, element }) }`); the core inspector knows nothing about Blazor.
- Added: `pk-nav-item` `group` (a group title in `pk-side-nav`: static, muted text, not focusable, skipped by the arrow keys, hidden while filtering, a divider in the icon rail); `pk-progress` `inline` (label, bar and value on one line); `pk-app-shell` `flush` (no body padding, so a workspace sits edge to edge; the safe-area insets stay); `pk-workspace` `--pk-workspace-nav-pad`, `--pk-workspace-main-pad` and `--pk-workspace-aside-pad` (per-pane padding, each falling back to `--pk-workspace-pad`); `pk-grid` `ratio` (unequal columns such as `2:1`, back to auto columns at 640px and below; new `--pk-grid-ratio`); `pk-input` `showLabel` (a visible label linked to the control, new `label` part). Each new prop has its `blazor/mappings` parameter (`Group`, `Inline`, `Flush`, `Ratio`, `ShowLabel`) (issue #21).
- Added: the Blazor element wrappers are generated (issue #2). `node scripts/generate-blazor.mjs` reads `core/dist/elements/api.json` and `blazor/mappings/<name>.json` and writes one Razor component per element into `blazor/src/PlainKit.Blazor/Generated/` (80 components, the enums they use, one event-args class per `pk-*` event, and `generated.manifest.json` listing what was skipped or still needs a type). Props become parameters, slots `RenderFragment`s, events `EventCallback`s with typed details, and a value driven by a change event is two-way (`@bind-Value`). `PkElementBase` loads the toolkit through `PkRuntime`; `wwwroot/PlainKit.Blazor.lib.module.js` (a Blazor JavaScript initializer, also generated) registers the `pk-*` events with Blazor. `--check` fails when the output is stale; CI runs it and the definition of done lists it. `PkCard`, `PkEmptyState`, `PkFieldList`, `PkStat` and `PkTable` (mapping `existing: true`) and `PkGallery` (hand-written) are skipped; `blazor/mappings/gallery.json` is now marked `existing`.
- Added: the SDK logs what it used to swallow (issue #16). Empty catch blocks and `.catch(() => {})` handlers in the runtime now log (warn, or debug for an expected fallback) or say why they are silent, and `tests/no-silent-catch.test.mjs` keeps it so; elements warn once per instance and prop when an enum value, a number or json cannot be used (`coerce` takes an optional report callback), and `pk-tabs` (value with no tab), `pk-icon` (name not in the sprite), `pk-image-gallery` (refused source), `pk-dialog` and `pk-drawer` (opened with no content), `pk-table` (columns or rows not an array) and `pk-input` (bad currency) say what went wrong; debug lines cover element defined, connected and prop changes, module load times and each tool's mount. New exports: `isLogEnabled(level, scope)` in `js/log.js`; `PkElement` gains `log`, `warnOnce` and `coerceProp`. `loadElements` no longer rejects (it logs a failed registry or module load).
- Added: logs viewer (`mountLogs`, issue #17) and logging settings (`mountLogSettings`, issue #18), built from SDK components: filter the SDK logger's entries by level, scope and text, see a row's detail, copy/export/import JSON, pause; set the global level, a level per scope and where each level is sent, send a test, save and reset. They are `dist/logs/` and `dist/log-settings/`, the dev tools' Logs and Logging tabs, a Logging section on the Settings page, and the `PkLogs` and `PkLogSettings` Blazor components.
- Added: versioning (issue #23): one version for the SDK and PlainKit.Blazor in `core/VERSION`, stamped into `dist/manifest.json`, `js/version.js` (`PK_VERSION`) and the NuGet package (`PkAssets.Version`, `PkRuntime.GetSdkVersionAsync`); `tools/versioning.mjs` (check, set, bump); the API baseline now covers each element's tag, props, events, slots, parts, CSS properties and methods; CI checks a release pull request; the release workflow checks the tag and marks pre-releases.
- Added: performance monitor (`mountPerformance`), dev console (`mountConsole`) and dev tools (`mountDevTools`: a dock on any page, Ctrl+`, or inline), all built from SDK components.
- Added: `PlainKit.Blazor` (net10.0): `PkGallery`, `PkCodeExplorer`, `PkScorecard`, `PkPerformance`, `PkConsole`, `PkStyles`, the `/_plainkit` dev tools page, `PkSnapshot`; the package serves a copy of `core/dist` (`scripts/publish-dist.mjs`).
- Added: `core/STANDARDS.md` (naming, tokens, modules, the dist pattern, CSP, keeping SDK and Blazor in step) and `core/site/guides/PROPOSAL.md` (a docs engine built from existing components, with its gaps).

### Changed

- Changed: the gallery's Guides page says "Coming soon" (a `pk-badge` above the empty state); the docs engine is undecided (issue #6).
- Changed: `pk-dialog`, `pk-drawer` and `pk-popover` install the declarative openers (`data-open`, `data-toggle`, `data-close`, `js/invokers.js`) the first time one connects, so a page that only uses the elements gets them without `initPlainkit()`, and a page with no overlay does not load the listener's work; `initPlainkit()` still installs them (idempotent per root). The overlays-and-navigation sample no longer wires them itself. Element sources changed, so the browser attestation must be re-run (issue #20).
- Changed: `pk-input` was at its 4 KB gzip element budget, so its source was tightened to fit the new label (one shared number reader for min, max and step, one event helper, one phone media query, the unused textarea and select selectors and the outer spin-button selector dropped); no budget was raised.
- Changed: the Blazor mapping moved out of the SDK element metadata into `blazor/mappings/<element>.json` (issue #26). The `blazor` block is gone from every `core/elements/*/*.meta.json` and from `dist/elements/api.json`; `validateApi` no longer requires it; the SDK gallery no longer shows the "Blazor equivalent" snippet and the "Blazor mapping" table (`blazorSnippet` is removed). The mapping checks now live in `scripts/tests/blazor-mappings.test.mjs` (run by CI and the release workflow). Parameters whose type is not defined in this repository yet are marked `todo` (issue #9).
- Changed: the page layer lives in `core/base/` (`utilities.css`, `spacing.css`, `typography.css`, `table-content.css` moved from `components/`, same cascade order and same `dist/plainkit.css`).
- Changed: the site's collapsing search field is a `pk-button` (icon) and a `pk-input type="search"`; it still dispatches `site-search`.
- Changed: sample meta `used` lists name the `pk-*` elements the markup uses (`node core/tools/samples-sync.mjs` rewrites them); the templates use `pk-grid` where they used the `split` class.
- Changed: Blazor component names are now `Pk` plus the tag in PascalCase (`pk-alert` is `PkAlert`, `pk-table` is `PkTable`); parameters are unchanged.
- Changed: site menu is Gallery, Files, Scorecard, Theme editor, Guides, Dev tools; the theme toggle moved into a settings menu with a Settings page; Templates and Spacing live in the Gallery tree.
- Changed: the build removes files in `dist/js` that no source produces any more (`staleDistJs`, tested); the leftover `dist/js/sdk.js` is gone.
- Changed: the old Spacing page (`site/spacing/`) only redirects to the gallery foundation `#/foundations/spacing`.
- Changed: the table and pagination element notes describe their behaviour in terms of `rows`, `columns`, `pk-sort`, `pk-filter`, `pk-page` and `pk-page-size`.

### Fixed

- Fixed: `pk-stepper` no longer throws `s.aria is not a function` when its steps are in the document before `pk-step` is defined (issue #38, the same upgrade-order bug fixed for `pk-tree`): it waits for the definition, then syncs again.
- Fixed (docs): the README examples that loaded `dist/plainkit.js` as a bare script did not start any element (the entry module only exports `initPlainkit`); they now call it. The package README no longer says every unmatched attribute goes on the element: a generated component throws on an attribute it has no parameter for (only components that list `ExtraClass`, such as `PkAlert`, take a class).
- Fixed: the master-detail pattern carried a no-op `flush` attribute on a `pk-list-group` (the prop is `variant="flush"`). Found by the skills test; the `pk-table` examples "Empty and loading" (`empty-text`) and "Expandable rows" (`expandable`, `detail-<n>` slots) in its meta use attributes that do not exist, and are left out of the skills until the meta is fixed.
- Fixed: the NuGet package no longer contains `Generated/generated.manifest.json` (it was packed as `content/` and `contentFiles/` and copied into consumers' projects); `scripts/tests/blazor-package.test.mjs` guards it.
- Fixed: every public enum and member in PlainKit.Blazor (`PkTheme`, `PkWidth`, `PkChrome`, `PkGalleryKind`, `PkLogLevel`) has an XML doc comment, so the build has no CS1591 warnings.
- Fixed: PlainKit.Blazor no longer throws out of the request pipeline when `IPkLog` (or a component) touches JavaScript while a page is prerendered; `PkRuntime.DisposeAsync` now ignores the "JavaScript interop calls cannot be issued at this time" error of a prerender scope. Found by driving the Playground in a real browser.
- Fixed: `pk-tree` no longer throws `aria is not a function` when it connects with items that are already in the page but not upgraded yet; it waits for `pk-tree-item` to be defined and updates again (issue #21).
- Fixed: the close button of a closable `pk-tab` is reachable by keyboard: it is a tab stop on the selected tab (the other tabs' buttons stay out, like the tabs themselves), and Enter or Space closes (issue #21).
- Fixed: a `flush` `pk-card` with a `heading` keeps the padding of its heading row and drops only the body padding (issue #21).
- Fixed: `pk-otp-input` no longer overflows a 320px window: the host and group are capped at 100% and the cells shrink below 2.75rem when the container is narrower (issue #21).
- Fixed: `pk-alert` fired `pk-dismiss` twice per click; phone layout of the site top bar and the gallery playground.
- Fixed: the gallery Elements overview now honours the `filter` option like Controls, and with `chrome="full"` every overview (home cards, Foundations, Controls, Elements, Samples) lists only what the mount's `kind` / `group` / `control` / `filter` leave (`filterTree` in `js/gallery-options.js`).
- Fixed: the gallery in a host page: the chrome fills a fixed-height container, the docked inspector no longer covers the page content, element pages and the Display menu work without the host calling `initPlainkit`, sample frames no longer show a stray scrollbar, controls cards no longer end in "..", and the host page's own title is kept.

### Removed

- Removed: the gallery's Controls section, its Samples > Building blocks group and the legacy Blazor parameter tables. Elements is the one component section; `#/controls/<group>/<id>` redirects to the element page when one has that name. `<pk-gallery kind="controls">` is still accepted and means `elements`. The scorecard and the size sweep now rank and measure elements and their examples.
- Removed: the gallery's Quality checks (toolbar button, `#/quality/run` page, `offscreenFrame`); the Scorecard is the place for quality scoring.
