# Icon design language

The source of truth for every icon in the SDK sprite (`core/icons.svg`, generated — see "Source and tooling" below).
This is phase 1 of issue #111: the grid, the rule set and the build. Coverage is the first real batch (what the SDK
already needs), not the full ~120-icon wishlist; the gallery browse page is deferred to the owner/presentation work.

## Grid

Confirmed by inspecting the 39 icons already in the sprite before this change (`search`, `settings`, `trash`,
`undo`, `edit`, ...): every one of them is drawn on a **24x24 viewBox**, stroke-only, in the Feather-style
convention already established here. New icons keep that grid exactly — do not introduce a second size.

- `viewBox="0 0 24 24"`, no `width`/`height` attribute (the `<use>` in `pk-icon` sizes it).
- **2px stroke**, applied once by `elements/icon/icon.css` (`stroke-width: 2`) — never set on a path.
- **Round line caps and joins** (`stroke-linecap: round; stroke-linejoin: round`), also applied once by the
  element's CSS. A source file never repeats or overrides it.
- **`fill: none; stroke: currentColor`**, again applied once by the element. A path never carries its own
  `fill` or `stroke` attribute — see "currentColor only" below.
- Live geometry sits inside a **2px margin** (a stroke centred on the outer edge would clip at small sizes):
  keep coordinates roughly within `[2, 22]` on both axes, the same optical margin the existing icons use
  (e.g. `search`'s circle is `r="8"` centred at `11,11`, `x`'s diagonals run `6` to `18`).

## Stroke width and joins

Fixed at the element level, not per icon:

```css
svg { fill: none; stroke: currentColor; stroke-width: 2; stroke-linecap: round; stroke-linejoin: round; }
```

A source `.svg` is just the shapes — `<path>`, `<line>`, `<polyline>`, `<polygon>`, `<circle>`, `<rect>`,
`<ellipse>` — with no presentation attributes of their own. This is what keeps every icon visually identical in
weight: change the stroke once, every icon changes together.

## currentColor only

No icon ever names a colour. The lint step (`core/icons/build.mjs`) rejects any `fill="..."` or `stroke="..."`
other than the implicit inheritance from the element's CSS, and rejects any `id` in the source file (the build
assigns the sprite `<symbol id>` from the filename; an id inside the artwork is dead weight that also risks
colliding with another symbol once inlined). This is what lets an icon sit in destructive-red text, muted
secondary text or an inverted dark surface and always read correctly — the same reason `pk-icon`'s CSS
resolves `color: inherit`.

## Optical sizing

`pk-icon` draws at four sizes (`sm` = `--space-4`, `md` = `1.25em`, `lg` = `--space-6`, `xl` = `--space-8`). A
single 24x24 grid has to read at all of them:

- Keep shapes closed and simple enough to survive being scaled down to `sm` (16px) — a detail that only shows
  at `xl` is a different icon's job, not this one's.
- Do not thin lines or add fine detail to "help" a large size look busier; the sprite is one grid, not a set of
  size-specific variants.
- Prefer a handful of primitives (a circle, a couple of lines, one path) over many short segments: it holds up
  better under scaling and keeps the file small.

## Do

- Reuse the shapes already in the sprite for a similar concept: `refresh` next to `undo`/`redo` (which already
  exist) should read as the same family, not a different stroke weight or corner style.
- Keep names kebab-case nouns or verbs with no synonyms (`copy`, not `duplicate` and `copy` both); check
  `core/icons/icons.json` before adding a name that might already exist under another spelling.
- Test a new icon at `sm` in both a light and a dark surface before adding it (the gallery's icon grid, once
  bootstrapped, shows every symbol in the sprite: `pk-icon name="..." size="sm"` next to `size="xl"`).

## Do not

- Do not add a filled icon, a two-tone icon or a gradient — the sprite is stroke-only, one colour
  (`currentColor`), forever (this is a compile-time rule, not a style preference: the lint step rejects it).
- Do not set `id`, `style`, `class`, `<script>`, `<style>`, or any colour attribute inside a source file.
- Do not hand-edit `core/icons.svg`, `core/icons/icons.json` or `core/icons/icons.d.ts` — they are generated by
  `core/icons/build.mjs` (wired into `node scripts/bootstrap.mjs`); edit the `.svg` files under `core/icons/src/`
  instead and re-run the bootstrap.
- Do not raise the sprite's size budget to fit an icon in; simplify the icon (per AGENTS.md, "size budgets are
  never raised").

## Source and tooling

Individual sources live at `core/icons/src/<name>.svg`, one bare `<svg viewBox="0 0 24 24">...</svg>` per file
(no `<symbol>` wrapper — the build adds that). `core/icons/build.mjs` is dependency-free (Node only) and:

1. Reads every `.svg` under `core/icons/src/`, in filename order (deterministic — no directory-listing order
   dependency).
2. Lints each one: `viewBox="0 0 24 24"` exactly, no `fill`/`stroke`/`style`/`class`/`id` attribute anywhere in
   the file, no `<script>` or `<style>` element, and a per-file size limit (see below).
3. Wraps each as `<symbol id="<name>" viewBox="0 0 24 24">...</symbol>` (the filename, without `.svg`, becomes
   the id — so the lint also rejects a filename that is not a lowercase kebab-case name) and writes
   `core/icons.svg` (CRLF, like every other generated file under `core/`).
4. Writes a typed name list: `core/icons/icons.json` (`{ "names": [...] }`, sorted) and `core/icons/icons.d.ts`
   (a TypeScript union type `PkIconName`).

Run it directly with `node core/icons/build.mjs`, or as part of the full build with `node scripts/bootstrap.mjs`
(it runs before `core/tools/build.mjs`, which copies the generated `core/icons.svg` into `core/dist/icons.svg`
the same way it always has). `core/icons.svg`, `core/icons/icons.json` and `core/icons/icons.d.ts` are
generated output: not tracked by git, rebuilt every time (see `scripts/generated.mjs` and `.gitignore`).

## Size budget

The sprite is loaded once per page and cached (browsers dedupe repeated `<use href="icons.svg#name">` fetches),
so its size is a one-time cost, not a per-icon one — but AGENTS.md's rule stands: set a budget once, from the
current size, and never raise it. The 39 icons the sprite carried before this change were 7,746 bytes raw. This
PR's batch (39 existing + the new first-batch icons audited in `core/icons/src/`) is well under
**16,384 bytes (16 KiB) raw**, which is this repository's budget for `core/icons.svg` going forward
(`core/icons/icons.test.mjs` fails the build if a future addition crosses it — the fix is to simplify or split
the sprite, never to raise the number). See that test's output for the exact current size and the icons that
make it up.
